# v0.1.6 — Bridge 认证、状态与配对恢复修复

修复 Bridge 进程存在、WebSocket 可达，但保存的凭据已经被 Relay 拒绝时，控制脚本和 doctor 仍看起来一切正常的问题。

## 本次更新

- Bridge 等待 Relay 的明确认证确认；失效凭据进入 `PairingRequired`，网络/认证服务暂时不可用进入 `Reconnecting`，不会自动删除凭据。
- 新增 `CodexCompanion.Bridge.exe pair`：自动定位实际凭据路径，备份旧凭据，显示新的 8 位配对码、URL 和二维码，手机配对完成后自动退出。
- 新增 `status --runtime` JSON；后台控制脚本分别显示进程、网络、认证、配对和 Ready，Start 有限等待真实状态。
- doctor 区分凭据缺失、格式损坏、DPAPI 无法解密、网络失败、Relay 拒绝和认证成功；认证探测不会替换已有 Bridge 会话。
- 修复安装器的配对完成判断，以及计划任务未继承当前 PowerShell 配置覆盖的问题。
- 统一模式 A 的 Compose 命令，显式指定 `.env` 和快速模式 Compose 文件。
- 相比上一版本，还包含双语 README、部署说明及产品演示文档更新。

## 升级顺序

**先更新 Relay，再更新 Windows Bridge。** 新 Bridge 需要新 Relay 提供认证确认；旧 Relay 无法提供确认时，不会报告 Ready。现有有效 DPAPI 凭据不会因升级自动重置。

模式 A 从源码更新：

```bash
cd /opt/codex-companion
git pull --ff-only
docker compose --env-file .env -f deploy/docker-compose.quick.yml up -d --build
docker compose --env-file .env -f deploy/docker-compose.quick.yml ps
```

预构建镜像：`ghcr.io/znnnnnnn-wil/codex-companion-relay:v0.1.6` 和 `ghcr.io/znnnnnnn-wil/codex-companion-web:v0.1.6`。使用镜像模式时，将 `.env` 的 `RELAY_IMAGE`、`WEB_IMAGE` 指向对应版本，再执行：

```bash
docker compose --env-file .env -f deploy/docker-compose.quick.yml -f deploy/docker-compose.images.yml pull
docker compose --env-file .env -f deploy/docker-compose.quick.yml -f deploy/docker-compose.images.yml up -d
```

模式 A 重启 Relay 后会丢失内存配对信息。停止旧版 Bridge、安装本版本后，执行：

```powershell
$bridgeControl = "$env:LOCALAPPDATA\CodexCompanion\Bridge\bridge-control.ps1"
$bridge = "$env:LOCALAPPDATA\CodexCompanion\Bridge\CodexCompanion.Bridge.exe"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $bridgeControl -Action Stop
& $bridge pair
# 手机完成配对、pair 自动退出后：
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $bridgeControl -Action Start
```

模式 B 继续支持 WSS 和 PostgreSQL 持久化，无数据库迁移。相对 `credentialPath` 现在以配置文件目录为基准；已有相对路径配置请核对，或改为原凭据文件的绝对路径。
